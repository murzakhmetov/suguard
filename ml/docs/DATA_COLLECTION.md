# Сбор парных данных SuGuard (браслет + эталонная глюкоза)

Модель глюкозы, которая работает **на вашем браслете**, можно обучить и проверить только на данных
с этого же браслета (MAX30102, красный 660 нм + ИК 880 нм, ваш корпус, ваша посадка на запястье),
сопоставленных с эталонными измерениями глюкозы. Открытые датасеты (BIG IDEAs, PPG-DaLiA) записаны
другими датчиками (Empatica E4, зелёный свет) — они годятся для проверки гипотезы и предобучения,
но не заменяют собственные данные.

## 1. Дизайн исследования

| Параметр | Минимум для пилота | Для валидации |
|---|---|---|
| Участники | 30 | 100+ |
| Состав | норма + преддиабет + СД2 (+ СД1/инсулин для широкого диапазона) | то же, сбалансированно по полу/возрасту/ИМТ/тону кожи |
| Длительность | 10–14 дней на человека | то же |
| Эталон | CGM (FreeStyle Libre 2/3 или Dexcom) + глюкометр ISO 15197:2013 | то же; часть точек — венозная кровь в лаборатории |
| Пар «PPG ↔ глюкоза» | ≥100 на человека, ≥7 дней | ≥300 на человека |

* **Этика:** до начала нужно одобрение локального этического комитета и информированное согласие
  (это медицинское исследование с персональными данными о здоровье).
* **CGM как эталон** даёт тысячи пар на человека, включая подъёмы после еды — без них модель увидит
  только «утреннюю» глюкозу и не научится ничему полезному. Уколы глюкометра нужны для калибровки
  CGM и как вход для персональной калибровки в приложении.
* **Разнообразие важнее количества точек:** обобщение на новых людей ограничено числом людей, а не
  числом измерений у одного человека.
* **Критерии успеха фиксируются заранее** (pre-registration), например: на отложенных людях и днях
  MARD после калибровки < 15 %, выигрыш ≥ 10 % у «только калибровки», ≥ 95 % точек в зонах A+B
  Parkes/Clarke. Иначе — честно сообщить, что глюкоза по PPG не подтверждена.

## 2. Что записывать

1. **Сырые окна браслета** — прошивка `firmware/suguard_raw_stream` в режиме `MODE_COLLECT`
   (каждые 10.24 с: 1024 отсчёта red + 1024 IR, 100 Гц, температура кристалла MAX30102).
   Для экономии батареи допустимо 60 с каждые 5 минут.
2. **Эталонная глюкоза** — экспорт CGM (CSV) + уколы глюкометра с точным временем.
3. **Еда** — фото/записи в трекере питания приложения (углеводы, время начала еды).
4. **Профиль** — возраст, пол, рост, вес, диагноз, препараты (особенно бета-блокаторы и инсулин).
5. **Заметки** — физнагрузка, сон, болезнь, смена посадки браслета.

## 3. Форматы файлов

`windows.jsonl` — одна строка на окно:

```json
{"user_id": "u17", "device_id": "SG-001", "ts": 1763100000, "fs": 100, "temp_c": 31.4,
 "red": [101234, 101201, ...], "ir": [143002, 142987, ...]}
```

`fingersticks.csv` (или экспорт CGM в тех же колонках):

```
user_id,ts,glucose_mgdl,source
u17,2026-11-14T08:05:00+05:00,104,meter
```

`meals.csv` — `user_id,ts,carbs_g,calories`; `profiles.csv` — `user_id,age,sex,height_cm,weight_kg`.

## 4. Обработка

```python
from suguard_ml.data.paired import build_from_device_logs
df = build_from_device_logs("windows.jsonl", "fingersticks.csv", "meals.csv", "profiles.csv",
                            tz_offset_h=5)          # Казахстан, UTC+5
df.to_parquet("data/suguard_paired.parquet")
```

```bash
python scripts/train_glucose.py --table data/suguard_paired.parquet --out models --name suguard
```

Скрипт выводит три протокола (случайное разбиение — только чтобы показать завышение; новые люди;
персональная калибровка на будущих днях), сравнение с базовыми моделями и с моделью «только
контекст», и выставляет `validated`. API показывает глюкозу как измерение только у валидированной
модели.

## 5. SpO2

Кривая SpO2(R) по умолчанию — референсная кривая Maxim. Для своего корпуса её нужно откалибровать
по медицинскому пульсоксиметру (`suguard_ml.signal.spo2.fit_spo2_calibration`). Диапазон 94–100 %
можно проверить на добровольцах в покое; точность ниже 90 % проверяется только в лабораторном
исследовании с контролируемой десатурацией (ISO 80601-2-61).
